## QA-01: успешный JSON неправильной структуры

Приоритет P1, статус: воспроизведено на mock, передать backend-владельцу для решения.
Шаги: `/api/products/detail?id=515291`, upstream HTTP 200 с массивом `[product]`.
Факт: backend отвечает 200 с тем же массивом. `_get()` проверяет HTTP и JSON,
но не схему. Риск: будущий AI примет некорректную карточку как достоверный tool result.
Предлагаемое ожидание: 502 или типизированная ошибка в AI tool adapter, без фактов в ответе.
Тест: `test_gap_detail_rejects_non_object_json`.
Текущий passthrough описан README; это пробел будущей безопасной интеграции,
а не нарушение уже согласованного detail-контракта (формальной схемы пока нет).

## QA-02: detail с другим ID

Приоритет P1, статус: воспроизведено на mock, решение за backend-владельцем.
Шаги: запросить ID 515291, upstream 200 с `{id: 999, ...}`.
Факт: backend возвращает 200 и другой ID. Риск: цена/остаток чужого товара могут
попасть в ответ или предложение корзины. Предлагаемое ожидание: 502 либо безопасный
отказ на границе tool adapter с проверкой идентичности. Тест:
`test_gap_detail_rejects_wrong_product_identity`.
Это не сообщение о наблюдавшейся подмене ID на живом EKT.

## Пробелы данных и интеграции (не исправлялись)

- Противоречие name 160А / properties 250А сообщено командой и описано frontend README.
  Endpoint сохраняет оба значения. Выбирать одно как правильное запрещено будущему AI.
- Сертификаты: отсутствие поля в проверенном detail не доказывает отсутствие сертификата.
  Положительный сценарий пока блокируется отсутствием подтверждённого источника.
- Нет источника условий покупки и контракта настоящей корзины. Демо frontend не является EKT-корзиной.
- Нет `/api/chat`, его typed response и tool hooks. 29 тестов требуют интеграционного adapter.
- CORS пока GET-only: будущему POST chat понадобится согласованное изменение backend;
  текущие тесты намеренно фиксируют текущий контракт, а не меняют его заранее.
- README backend говорит, что наличие отдельно не проверялось, тогда как пользователь
  сообщил более поздние detail-наблюдения. Нужен обезличенный raw fixture и обновлённая
  schema от владельца backend, а не догадки о структуре stores/properties/offers.
- Живые цены/остатки, совместимость аналогов, сертификаты, условия покупки, latency,
  privacy и настоящая корзина не покрываются этим offline HTTP-прогоном полностью.

Production `backend/`, frontend и существующие тесты не редактировались.
Никаких `/api/chat`, LLM интеграций, merge или отправки в main не выполнялось.
