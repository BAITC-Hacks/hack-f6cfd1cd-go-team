# Демонстрационный магазин EKT

## Чат через backend

Реализован по `chat-api-contract.md` из ветки `origin/backend`, commit `2b67e8b` (резервный режим уже включён в контракт). Поиск каталога не изменён.

- `chat-api.js`: POST `http://127.0.0.1:8000/api/chat`, JSON `{message, session_id}`, без cookies/Authorization. 1–2000 символов. Клиентский таймаут 160 секунд с учётом серверного лимита 150 секунд.
- Первый запрос передаёт null; последующие используют UUID из успешного ответа. История хранится backend, фронтенд не придумывает поле history. Сессия живёт только в памяти вкладки. «Новый диалог» отменяет ожидание и очищает ID. Перезагрузка тоже начинает новую сессию.
- `live-chat.js`: текст ответа и структурированные products выводятся безопасными DOM-элементами. Режимы fallback и openai отображаются одинаково: mode не меняет сообщения, карточки или работу сессии. Общая подсказка рекомендует указывать артикул в каждом сообщении. Отсутствующие tools_used, image и url поддерживаются.
- Для source=ekt_detail выводится quantity из EKT; null — «нет данных», 0 — именно 0. Для source=sqlite наличие не объявляется актуальным. Цена не дополняется выдуманной валютой или единицей. Количество не привязывается к городу из интерфейса: поле города в контракте отсутствует.
- Одновременно отправляется одно сообщение. Ошибки отображаются по status/code. Только session_not_found сбрасывает ID; catalog_error с HTTP 404 не сбрасывает сессию. Ошибки 422 имеют стандартный формат FastAPI. Автоматического повторения нет; пользователь может вернуть вопрос в поле ввода или начать новый диалог.
- Ни кнопок добавления, ни изменения корзины из чата нет. Старый локальный answer() и сценарии подтверждения удалены. Нет запросов напрямую в EKT detail или OpenAI. Fallback выполняет backend, клиент не заменяет ошибку демонстрационным ответом.
- CORS backend должен разрешать POST и Content-Type для `http://127.0.0.1:5173`. Backend запускается отдельно на той же машине; ключи остаются у backend.

Проверка: отправить «Есть ли товар 200300285_ в наличии и сколько он стоит?», проверить mode, карточку и повторный запрос с тем же session_id. Затем нажать «Новый диалог» и проверить null в первом запросе. Backend может работать без OpenAI через свой deterministic fallback.

Самостоятельный фронтенд для кейса HackAlem AI. HTML, CSS и JavaScript ES modules, без установки зависимостей. Требуется Node.js 20+.

## Запуск

```sh
cd frontend
npm run dev
```

Откройте http://127.0.0.1:5173. Для другого порта задайте переменную окружения `PORT`.

```sh
npm test
npm run check
```

## Возможности

- Поиск по названию, бренду и двум артикулам; категории, бренды, наличие, сортировка.
- Выбор Алматы, Астаны или Шымкента и остатки по городу.
- Карточка товара, характеристики, избранное, демонстрационная корзина.
- Изменение количества, удаление позиции, выгрузка списка в TXT.
- Чат: POST /api/chat, сессия в памяти вкладки, карточки товаров из tools и отображение режима openai/fallback.
- Чат работает только на чтение: не создаёт предложения и не изменяет корзину. Демо-корзина отдельно доступна для тестовых товаров каталога.
- Адаптивный интерфейс: на десктопе чат справа, на мобильном — отдельная панель.

## Данные и ограничения

`catalog.js` содержит 8 позиций из снимка EKT API от 23.09.2026. Названия, артикулы, цены и ссылки на изображения взяты из полученных ответов. Только для `515291` использованы проверенные остатки (Алматы 5, Астана 8, сумма двух складов Шымкента 3). Для других позиций остатки синтетические и помечены в интерфейсе. Отображение KZT и «шт.» — демонстрационные допущения; уточнить валюту, единицы и кратность перед интеграцией. Изображения загружаются с ekt.kz; при недоступности показывается текстовая заглушка. Шрифт Manrope загружается с Google Fonts, есть системный fallback.

У `515291` название и описание указывают 160 А, а свойство NOMINALNYY_TOK — 250 А. Противоречие сохранено в демо-карточке. Ответы backend отображаются без подмешивания этих демонстрационных данных. Сертификаты и условия покупки не выдумываются.

Чат подключён к backend. Корзина, город и избранное демо-подборки сохраняются в localStorage; ID сессии чата не сохраняется и не передаётся между вкладками. Заказ, оплата, резервирование и загрузка вложений не реализованы. Учётные данные API в проект не включены.

## Поиск через backend

Подтверждён backend `http://127.0.0.1:8000` и endpoint `GET /api/products/search?q=...`. Точный origin frontend для CORS: **`http://127.0.0.1:5173`**. `http://localhost:5173` является другим origin; если команда использует и его, разрешить отдельно. При смене порта меняется origin.

В `api.js` реализован `fetchProductSearch(query, options)`: кодирование запроса, проверка длины 1–200 символов после trim, таймаут 10 секунд, отмена через AbortSignal. Только GET, `credentials: omit`, без Authorization. Ошибки 422 и 503 обрабатываются по статусу, без зависимости от текста `detail`.

По умолчанию выбран **«Поиск в каталоге EKT»**. Ввод в верхней строке отправляет запрос после 350 мс паузы; Enter запускает сразу. Очистка строки отменяет запрос, пустой q не отправляется. Устаревшие ответы не заменяют новые. Начальный экран предлагает ввести запрос: endpoint получения всего каталога не предполагается.

`search-model.js` проверяет согласованный ответ: `query`, `match_type`, `count`, `items`, `source: "sqlite"`, `synced_at`, `catalog_complete`; `pages_scanned` интерфейс не использует. Товар содержит `id`, `name`, `article`, `price`, `image`, `url`. `url_api_detail` намеренно игнорируется. Время синхронизации отображается в местном времени браузера. При `catalog_complete: false` выводится предупреждение о неполной выдаче. Отсутствующая цена отличается от нуля; строковая цена сохраняется. Валюта и единица не назначаются автоматически: контракт их не содержит.

`live-search.js` выводит внешние строки через `textContent`; ссылки и изображения разрешены только с HTTPS-хостов `ekt.kz` и `www.ekt.kz`, без userinfo. При отсутствии картинки есть заглушка. Товар можно открыть в отдельной карточке или на публичном сайте EKT. Остаток всегда «Наличие уточняется», характеристики и сертификаты не выдумываются. Реальные товары нельзя добавить в локальную демо-корзину, даже если ID совпадает с тестовым товаром.

Кнопка **«Демо-подборка»** отдельно возвращает прежние 8 товаров и локальные фильтры. Автоматической подмены реальных результатов демо-данными при ошибке нет. В режиме API фильтры категории, бренда и наличия отключены, потому что поиск не возвращает эти поля. Сортировка применяется только к полученному массиву; исходный порядок сохраняется при выборе «рекомендуемые». Неизвестные цены размещаются в конце. Серверная пагинация не добавлялась: параметры не согласованы.

Backend должен работать на том же компьютере на порту 8000. `127.0.0.1` не указывает на компьютер тиммэйта. Для другого адреса изменить параметр `baseUrl` в вызове клиента после согласования доступного адреса. CORS не обходится через frontend-прокси. Backend-файлы, синхронизация и рабочая SQLite этой задачей не изменяются.

Чат подключён отдельно. Серверная корзина, самостоятельный вызов detail и вложения пока не подключены. Basic Auth EKT остаётся только на backend в `.env`, вне Git и клиентского кода.

### Проверка живого поиска

1. Запустить согласованный FastAPI backend на `127.0.0.1:8000` с синхронизированной SQLite.
2. Запустить frontend, открыть именно `http://127.0.0.1:5173`.
3. Ввести `200300285_`: ожидается товар 515291, цена 64920, дата синхронизации и неизвестное наличие.
4. Ввести `EKT_NO_MATCH_9d013b`: ожидается пустая выдача.
5. Остановить backend: должна появиться ошибка с кнопкой повторного поиска, без тестовых товаров.
6. При 503 показывается недоступность каталога; пустая успешная выдача от неё отличается.
