# API каталога EKT

Источник: «ИИ-ассистент для чата на сайте ekt.kz ДАННЫЕ.docx». Ниже перенесены сведения документа; выданные логин и пароль намеренно исключены.

## Авторизация

В документе указана Basic Auth. Настройки серверной части:

- `EKT_API_BASE_URL` — `https://ekt.kz/api`.
- `EKT_API_USERNAME` — выданный организаторами логин.
- `EKT_API_PASSWORD` — выданный организаторами пароль.

Названия переменных выбраны для этого набора документации, а не заданы организаторами. Передавайте их в механизм HTTP Basic Auth серверного HTTP-клиента. Не передавайте реквизиты во frontend, сообщения модели, логи или URL. Не сохраняйте готовый заголовок Authorization в Git.

## Адреса из документа

| Назначение | Адрес |
| --- | --- |
| Список всех товаров | https://ekt.kz/api/products |
| Переключение страниц: пример второй страницы | https://ekt.kz/api/products?page=2 |
| Детальная информация по товару: пример ID | https://ekt.kz/api/products/detail?id=515291 |

Документ указывает `page=2` «и так далее». Значение `515291` — пример идентификатора в исходном документе.

## Что в документе не описано

Нет формальной спецификации HTTP-методов, схемы JSON-ответов, размера страницы, признака последней страницы, кодов ошибок, лимитов запросов или параметров поиска. Не подтверждены отдельные API корзины, оформления заказа и условий покупки. Не придумывайте такие возможности как уже существующие.

Для реализации нужно проверить ответы списка и карточки через выданный доступ, уточнить правила пагинации и реальные поля. Перечень желаемых данных в ТЗ не является подтверждённой схемой ответа API. Примеры ответов сохраняйте только после проверки и удаления чувствительных данных.

Запросы к API при подготовке этого пакета не выполнялись; доступность адресов и содержимое ответов не проверялись.

## Проверка при реализации поиска (23 сентября 2026)

При последующей проверке `GET /products/detail?id=515291` получен объект с полями `id`, `name`, `article`, `description`, `price`, `quantity`, `stores`, `image`, `url`, `offers`, `properties`. На момент проверки `price=64920`, `quantity=23`; склады содержат `id`, `name`, `quantity`. Поля/ссылки сертификатов в этой карточке отсутствуют. Это не подтверждает их отсутствие у других товаров. Название/описание содержат 160 А, тогда как `properties.NOMINALNYY_TOK` содержит `250 А`; оба значения передаются без исправления.

Позднее интеграция проверена на реальном API через существующий EktService:

- GET списка возвращает объект `page`, `per_page`, `count`, `items`. На проверенных страницах `per_page=20`, `count=20`; это не общее количество товаров.
- Элементы `items` содержат `id`, `name`, `article`, `price`, `image`, `url`, `url_api_detail`, `offers`. `image` может быть `null`.
- Страницы 1, 2, 3 и 100 содержат разные товары. Страницы 1000 и 100000 возвращают товары первой страницы, хотя `page` отражает запрошенный номер.
- `q=EKT_NO_MATCH_9d013b` на первой странице не отфильтровал товары. Поддержка серверного поиска не подтверждена; другие названия параметров не предполагаются.
- На странице 2 найден ID `515291`, артикул `200300285_`, название `027228 АВ DRX250 MT 3ф 160А 18ka Legrand (1)`.

Это наблюдения, а не полная спецификация API. Команда синхронизации обходит `page`, обрабатывая повтор первой страницы как конец каталога. Поисковый endpoint теперь использует только локальный SQLite. Credentials и заголовки авторизации в документацию не включены.
