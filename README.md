# EKT.kz — backend каталога

Python + FastAPI: получение списка, карточки товара и поиск по каталогу EKT через Basic Auth. LLM, чат, frontend, корзина, аналоги и вложения пока не реализованы.

## Устройство

- `backend/main.py` — FastAPI и три GET-маршрута.
- `backend/config.py` — настройки из `.env` в корне; переменные окружения имеют приоритет.
- `backend/ekt_service.py` — EktService, запросы к EKT и обработка ошибок.
- `requirements.txt` — зависимости.
- `tests/test_backend.py` — проверки без сети и реальных credentials.
- `tests/test_search.py` — поиск, пагинация, приоритет артикула и ошибки обхода.

Браузер → FastAPI (проверка параметров) → EktService (Basic Auth) → EKT API → JSON → браузер. HTTP-клиент создаётся при запуске и закрывается при остановке. Credentials не передаются в ответах или URL; тела ошибок EKT наружу не возвращаются.

Список EKT имеет поля `page`, `per_page`, `count`, `items`. Товары содержат `id`, `name`, `article` и дополнительные поля. Список и карточка возвращаются без преобразования. GET-запросы проверены на реальном API. Данные не сохраняются; базы данных нет.

## Локальный запуск (macOS / Linux)

Из корня репозитория, Python 3.9 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

Заполните локальный `.env` реквизитами организаторов:

```dotenv
EKT_API_BASE_URL=https://ekt.kz/api
EKT_API_USERNAME="выданный_логин"
EKT_API_PASSWORD="выданный_пароль"
```

Подсказки выше нужно заменить настоящими значениями. `.env` исключён из Git. Не добавляйте исходный документ с реквизитами в репозиторий.

```bash
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

После изменения `.env` перезапустите сервер. Без credentials сервер и Swagger запускаются, но запросы каталога возвращают 503. Credentials нужны при первом обращении к каталогу.

## Проверка в браузере

- Первая страница: http://localhost:8000/api/products
- Вторая страница: http://localhost:8000/api/products?page=2
- Товар: http://localhost:8000/api/products/detail?id=515291
- Swagger: http://localhost:8000/docs

`page` по умолчанию 1, `id` обязателен; оба — положительные целые числа. Некорректные параметры дают 422 без обращения к EKT.

Ошибки возвращаются как `{"detail": "описание"}`:

| HTTP backend | Причина |
| --- | --- |
| 503 | Нет credentials или EKT вернул 429 |
| 504 | Таймаут EKT: 5 секунд на соединение, 15 на остальные сетевые операции |
| 404 | EKT вернул 404 |
| 502 | Ошибка сети, авторизации EKT, другой неуспешный статус или некорректный JSON |

Редиректы не выполняются автоматически. Товар `515291` найден на второй странице: артикул `200300285_`, название `027228 АВ DRX250 MT 3ф 160А 18ka Legrand (1)`. Наличие на складе отдельно не проверялось.

## Поиск товаров

`GET /api/products/search?q=...` ищет без учёта регистра по названию и артикулу. Внешние пробелы запроса удаляются; пустой запрос или более 200 символов дают 422.

Серверный поиск EKT не документирован. Проверка `q` с заведомо отсутствующей строкой вернула обычную первую страницу, поэтому этот параметр в EKT не передаётся. Наш сервис последовательно вызывает существующий `get_products(page)`.

- Точное совпадение артикула имеет приоритет: возвращаются точные совпадения на первой найденной странице, обход прекращается. Это не гарантирует нахождение дублей артикула на последующих страницах.
- Если точного артикула нет, собираются совпадения по подстроке в `name` или `article` со всех страниц. Повторные ID не дублируются.
- Конец обхода — пустой `items` или повтор первой страницы: фактический EKT возвращает первую страницу при выходе за границы каталога. `count` — количество элементов страницы, не всего каталога. Короткая страница сама по себе не завершает обход.
- Повтор другой страницы, неожиданный формат или ошибка EKT дают ошибку, а не неполный успешный результат. Защитный предел 10 000 страниц также даёт ошибку.

JSON поиска: `query`, `match_type` (`exact_article` / `substring`), `count` (число результатов), `items` (исходные товары), `pages_scanned`, `catalog_complete`. Для раннего точного совпадения `catalog_complete=false`; для полного обхода — `true`. Пустой результат считается достоверным только после полного обхода.

Примеры реальных артикулов:

- http://localhost:8000/api/products/search?q=200300285_
- http://localhost:8000/api/products/search?q=310100080_
- http://localhost:8000/api/products/search?q=RM22UA23MR

Поиск по названию, например `q=Legrand`, может занимать несколько минут: в каталоге более 100 страниц, и пока нет подтверждённого серверного фильтра или локального индекса. Каждый новый поиск заново читает страницы; быстрый поиск всего каталога потребует отдельного решения по загрузке/обновлению каталога. При изменении каталога во время обхода API не гарантирует единый снимок данных.

## Автоматические проверки

```bash
python -m unittest discover -s tests -v
```

Проверки используют HTTPX MockTransport и фиктивные значения. Они не обращаются к EKT и не читают реальный `.env`.
