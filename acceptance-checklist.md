# Чек-лист приёмки

Производный документ по `requirements.md`; не заменяет исходное ТЗ. Конкретные артикулы и ожидаемые значения подбираются по используемому набору данных.

## Пять Must have из раздела 7

- [ ] Существующий артикул: ответ возвращает верное наличие и технические характеристики из каталога; если сертификат есть в базе, возвращается его файл или ссылка.
- [ ] Позиция с нулевым остатком: предложен минимум один релевантный аналог с кратким обоснованием.
- [ ] Вопросы об оплате, доставке и минимальной партии: даны содержательные ответы на основе подтверждённых условий.
- [ ] Добавление: до явного подтверждения клиента корзина не меняется; после подтверждения количество не превышает остаток.
- [ ] После добавления: прямая ссылка открывает актуальное состояние корзины/оформления заказа.

## Остальные условия кейса

- [ ] Единое окно чата поддерживает свободный текстовый запрос.
- [ ] Обрабатываются входные фото и файлы Excel, Word, PDF, JPEG. В кейсе они указаны как входные данные, а не как опциональные функции; точные расширения и лимиты нужно уточнить.
- [ ] Используется контекст диалога в рамках сессии.
- [ ] Задержка ответа соответствует формулировке «единицы секунд»; точный порог в ТЗ не задан.
- [ ] Ни состав корзины, ни заказ не меняются без явного подтверждения клиента.
- [ ] Нет недостоверных сведений о цене или наличии.
- [ ] Платёжные данные клиента не запрашиваются и не хранятся.
- [ ] Учтены приватность клиента и защита от несанкционированного изменения корзины/заказа.
- [ ] Объясняется выбор аналога.
- [ ] Учтена совместимость с текущей платформой сайта, проверены desktop и mobile.
- [ ] Подготовлен репозиторий и README с архитектурой, запуском и описанием данных.
- [ ] Набор данных репрезентативен; при использовании разрешённых анонимизированных или синтетических данных сохранена структура полей.

## Опциональные функции из раздела 8

- [ ] Казахский язык.

- [ ] Сохранение истории для авторизованных пользователей.
- [ ] Эскалация сложных вопросов менеджеру.
