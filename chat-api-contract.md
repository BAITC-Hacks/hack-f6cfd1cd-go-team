# POST /api/chat — MVP

## Demo/session cart: подтверждение добавления

Это только демонстрационная корзина в памяти backend-сессии, не корзина ekt.kz. Реального API корзины, бронирования остатков, оформления заказа и checkout/cart URL нет. Упоминания отсутствия корзины в прежних разделах ниже относятся к настоящей корзине сайта.

Каждый успешный ответ теперь содержит `cart: {"type": "demo_session", "items": []}` и `pending_confirmation` (объект или null). Позиция cart.items: `product_id`, `article`, `name`, `quantity`. В отличие от `products[].quantity` (остаток EKT), `cart.items[].quantity` — добавленное количество.

1. Сообщение `Добавь 2 штуки товара 200300285_` ищет точный артикул в SQLite и получает актуальный detail. Если количество допустимо, сохраняет `pending_confirmation: {"product_id": 515291, "article": "200300285_", "quantity": 2}`; cart.items пока пуст.
2. Следующее отдельное сообщение `Да, добавь` с тем же session_id повторно получает detail и проверяет суммарное количество (уже в demo-cart плюс добавляемое) относительно актуального остатка. Только после этого меняется cart, pending_confirmation становится null.

Подтверждения: «Да, добавь» / «Да добавь» (также «добавьте»), без учёта регистра и конечных .!?. «Да» без команды не считается подтверждением. «Нет», «Отмена», «Отмени» отменяют ожидание. Любой иной ответ при ожидающем подтверждении отменяет его и не меняет корзину; новый корректный запрос добавления заменяет предыдущий. Повторное подтверждение без pending ничего не добавляет.

Поддерживается только простой формат: «Добавь N штуки товара АРТИКУЛ» (штук/штука/штуку/шт., добавьте, необязательное «в корзину»). N — положительное целое число. Запросы со свободными инструкциями, включая попытки обойти подтверждение, не выполняются. Обе стадии обрабатывает backend до OpenAI; модель не имеет инструментов изменения корзины. mode остаётся `fallback` как обозначение детерминированного ответа.

Недостаточный/неизвестный остаток, нулевое количество, неоднозначный артикул дают HTTP 200 с объяснением и неизменённой корзиной. Сетевая ошибка detail возвращается как catalog_error. При ошибке подтверждения ожидание сбрасывается: нужно новое предложение, а не повтор операции. Конкурентный запрос той же сессии получает 409.

Корзина и pending живут только в одной сессии/процессе, исчезают при истечении TTL, вытеснении или перезапуске. Корзина не гарантирует наличие на момент будущей покупки. Для демонстрации используйте один worker и храните session_id отдельно для каждого пользователя.

Реальная двухшаговая проверка: товар 515291, остаток EKT 23; запрос добавления 2 шт. → пустая demo-cart и pending; подтверждение → quantity=2 в demo-cart. Обе стадии HTTP 200, 0,162 и 0,100 секунды соответственно.

## Аналоги при нулевом остатке

Ответ дополнен `analogs` (по умолчанию []). После detail с quantity=0 вызывается AnalogService: до трёх поисков SQLite и трёх detail кандидатов, общий таймаут 25 секунд. OpenAI получает результат в `analog_search` (не более одного подбора за ход), fallback добавляет объяснение в message. Search/detail endpoints не изменены.

Кандидаты ранжируются по совпадению токенов названия. Принимается первый с положительным актуальным остатком, если полностью совпадает нормализованное название с минимум двумя буквенно-цифровыми обозначениями либо совпадают минимум три технических свойства исходника из явного списка и два токена названия. Во втором случае все сравниваемые свойства исходника должны присутствовать у кандидата. Противоречие общих технических свойств исключает кандидата. Артикулы, налоги и рекламные флаги не используются как технические характеристики. Это эвристика по данным, не правила электротехнической совместимости.

Элемент `analogs`: `source_product_id`, `product` (id/name/article/price/quantity/image/url), `quantity`, `explanation`, `matched_properties`, `disclaimer`. Пустой `matched_properties` допустим при совпадении названия: объяснение явно ссылается на обозначения из него. Если кандидат не найден или проверка недоступна, возвращается честное сообщение. Полная взаимозаменяемость не заявляется.

Реальная проверка: ярп4520 (ID 45357), остаток 0 → 150200474_ (ID 18284), остаток 341. Совпало название LED STARK, включая 30W, 2400Lm, d98x180, 4000K, IP20. HTTP 200, 1,241 секунды, mode=fallback. Значения могут измениться. Корзина и вложения не добавлены; упоминания отсутствия аналогов в старом описании этапа ниже заменены этим разделом.

Backend: `http://127.0.0.1:8000`. CORS: только `http://127.0.0.1:5173`, GET/POST, Content-Type, без cookies и wildcard.

## Резервный режим

OpenAI остаётся основным режимом. При отсутствии ключа, ошибке OpenAI (включая 401/429, недоступную модель, сеть) или таймауте основного режима выполняется deterministic fallback. Модель не подменяется. Ответ дополнен `mode`: `openai` или `fallback`; остальные поля сохранены. Fallback не является LLM.

Fallback выделяет до 30 отдельных токенов-кандидатов (буквы, цифры, подчёркивания, внутренние дефисы/точки/слеши), вызывает существующий SQLite search и принимает только точный артикул без учёта регистра. Артикулы с пробелами в этом минимальном режиме не поддерживаются. При единственном совпадении вызывает EKT detail и выводит исходные name/price/quantity; валюту и единицы не добавляет. Если данных нет, явно сообщает это. Несколько совпадений требуют уточнения. Для нового сообщения нужен явный артикул; свободное понимание диалога fallback не реализует.

`tools_used` в fallback — реально выполненные backend-операции, а не вызовы LLM. Ошибки SQLite/EKT по-прежнему возвращаются как `catalog_error`, без подмены актуальных данных устаревшими. Общий таймаут 150 секунд (до 120 секунд основного режима и остаток для fallback). История fallback сохраняется с теми же ограничениями.

Прежние ошибки `openai_not_configured`, `openai_auth_error`, `model_unavailable`, `openai_rate_limit`, `openai_error`, `openai_timeout` из таблицы ниже теперь запускают fallback вместо возврата этих ошибок frontend. Остальные ошибки контракта сохраняются.

## Запрос

```http
POST /api/chat
Content-Type: application/json
```

```json
{
  "message": "Есть ли товар 200300285_ в наличии и сколько он стоит?",
  "session_id": null
}
```

`message` — обязательная строка 1–2000 символов, не только пробелы. `session_id` — необязательный UUID или null. Первый запрос без ID создаёт сессию. Для продолжения frontend передаёт ID из ответа. Неизвестный/истёкший ID возвращает 404; начните новый диалог без ID.

## Успех: HTTP 200

Структура ответа (условный пример, не реальные данные EKT):

```json
{
  "session_id": "11111111-1111-4111-8111-111111111111",
  "message": "Текст ответа на основе данных инструментов",
  "products": [
    {
      "id": 42,
      "name": "Тестовый товар",
      "article": "EXAMPLE",
      "price": 123,
      "quantity": 7,
      "image": null,
      "url": null,
      "source": "ekt_detail"
    }
  ],
  "tools_used": ["search_products", "get_product_detail"]
}
```

`products` формирует backend из данных tools, а не из текста модели. Это найденные/использованные товары текущего хода, без дубликатов ID. Detail заменяет данные поиска. Поля: `id`, `name`, `article`, `price`, `quantity`, `image`, `url`, `source`. Отсутствующие значения — null. Цена сохраняет тип источника (number/string/null). `source` — `sqlite` или `ekt_detail`; SQLite не подтверждает актуальную цену/наличие. Для неизвестного количества frontend должен показать «нет данных», не 0. Валюта в контракте не задаётся, если её не предоставил источник.

`tools_used` — названия действительно выполненных tools в порядке вызова (возможны повторы). Пустой массив допустим для общего ответа без фактов о товаре. `products` также может быть пустым.

## Ошибки

Ошибки чата:

```json
{
  "error": {
    "code": "model_unavailable",
    "message": "Модель gpt-5.6-luna не найдена или недоступна API-проекту. Подмена модели не выполнялась."
  }
}
```

| HTTP | code | Действие frontend |
| --- | --- | --- |
| 404 | session_not_found | Начать без session_id |
| 409 | session_busy | Дождаться предыдущего ответа |
| 429 | openai_rate_limit | Сообщить о лимите/квоте, не повторять автоматически |
| 503 | openai_not_configured / openai_auth_error | Серверный ключ отсутствует/отклонён |
| 503 | model_unavailable | Проверить доступ API-проекта к выбранной модели |
| 503 | chat_busy | Сервер занят |
| 502 | openai_error | Ошибка OpenAI/конфигурации |
| 502 | invalid_tool_call / tool_limit / incomplete_response / empty_response / tool_output_too_large | Ответ не получен, предложить уточнить запрос |
| 504 | openai_timeout / chat_timeout | Таймаут |
| 404/502/503/504 | catalog_error | Ошибка SQLite/EKT, сообщение в error.message |

Ошибки валидации FastAPI имеют HTTP 422 и стандартный объект `{"detail": [...]}`, а не `error`. Например, неверный UUID или отсутствие message. Frontend ориентируется на статус/code, не на точный текст message. Сырые ошибки OpenAI и credentials не возвращаются.

## Контекст и ограничения

- История в памяти одного процесса: до 100 сессий, 6 завершённых ходов, 60 000 символов сериализованной истории на сессию.
- TTL: 30 минут неактивности. При заполнении удаляется самая старая неактивная сессия; при перезапуске все сессии исчезают. Запускайте MVP одним worker.
- Одновременные сообщения одной сессии дают 409. Не делитесь session_id между пользователями; авторизация пользователей в этот этап не входит.
- Один ход: максимум 5 обращений Responses, 6 tool-вызовов, до 1600 выходных токенов на ответ модели, общий таймаут 150 секунд. SDK retries отключены, модель автоматически не подменяется.
- В search tool передаются максимум 10 результатов с исходным count и флагом truncated; endpoint `/api/products/search` не изменён. Tool output ограничен 40 000 символов; слишком большой ответ вызывает ошибку, а не скрытое урезание карточки.
- История сохраняется только при успешном ответе. В OpenAI передаются сообщение, ограниченная история и результаты tools, но не серверные credentials. Responses вызывается с `store=false`.
- Правила запрещают выдумывать сведения, требуют detail для актуальной цены/остатков и раскрытия расхождений данных. Эти инструкции модели не являются математической гарантией отсутствия ошибок; структурированные products получаются напрямую из tools.
- Только чтение каталога. Корзины, аналогов, файлов и других tools нет.

## Настройка

В локальном `.env`:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-luna
```

Заполните ключ локально, не добавляйте в Git. После изменения перезапустите backend. Официальный SDK: `openai==2.48.0`; Responses API. При недоступности модели backend включает mode=fallback, не выбирая другую модель.

```bash
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
curl -X POST http://127.0.0.1:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Есть ли товар 200300285_ в наличии и сколько он стоит?"}'
```

Официальные источники: [SDK](https://developers.openai.com/api/docs/libraries), [function calling](https://developers.openai.com/api/docs/guides/function-calling), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna).
